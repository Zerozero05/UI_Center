# Windows 组件与规范工作台

工作台用于查找组件、操作真实预览，再把用法与来源带入目标项目。v1.2.1提供18个用 Python 标准库 Tk/ttk/Canvas 编写的组件，继续保留原主题、ActionBar 和 TaskPanel 入口，并修正保存位置。Windows运行包自带Python/Tcl/Tk，无需安装开发环境；当前正式状态见[发行说明](releases/v1.2.1.md)。

## 下载与启动

从 [GitHub Releases](https://github.com/Zerozero05/UI_Center/releases) 下载 Windows x64 运行包，用 `SHA256SUMS` 对照文件哈希。优先使用便携 ZIP：解压后双击 `UI_Center.exe`，保留整个 `_internal` 目录，不从压缩包内直接启动。

单文件 EXE 使用同一功能和内容，启动时将必要运行库释放到临时目录，正常退出后由打包运行时处理。它减少可见文件数量，不代表运行时没有额外磁盘占用。程序无需管理员权限，也不安装系统服务。

## 查找、试用与采用

1. 左侧默认进入“组件库”；“设计规范”和“资料与来源”分别查规则与原文。平台、场景与搜索可以组合使用；支持中文名称、英文别名及 `shummer` 搜索 Shimmer。
2. 选中 Tkinter 组件后，在“实时预览”调整参数并操作真实控件。“重置”恢复该预览的默认值；模拟任务只存在于示例，不处理你的文件。
3. “中文用法”说明用途、不适用条件、参数、接入与依赖；“示例与源码”显示当前内嵌预览参数对应的 Python 示例和源码/参数文件入口。设计规范使用单独的“规范 / 原文”视图。
4. “复制示例”读取当前内嵌预览的参数；“AI 说明”还带上条目、固定来源、适用边界和许可。原有 Tkinter/Android 条目复制各自文档中的精确用法；规范条目复制原文。
5. 需要更大空间时打开“独立预览”。它使用同一个组件实现，参数和模拟任务与内嵌预览各自独立；复制当前参数以主窗口的内嵌预览为准。“重置此组件”恢复该预览默认值。
6. 按 [源码复制与更新](consumption.md)复制完整 `ui_center` 包和 `tokens/design-tokens.json`，再将回调接到自己的业务。仅复制一段示例代码或单个类文件不能替代依赖文件。

| 组件组 | 实际 Tkinter 组件 |
| --- | --- |
| 加载（7） | Spinner、ProgressBar、CircularProgress、Skeleton、Shimmer、LoadingButton、PageLoader |
| 弹层（5） | Dialog、ConfirmDialog、Drawer、Popover、Tooltip |
| 导航（3） | Tabs、Accordion、SegmentedControl |
| 反馈（3） | InlineAlert、Toast、EmptyState |

以上18项是 Tkinter 实现；Web 与 Android 的适配说明表示可借鉴的状态和交互规范，本次没有新增对应平台的18个控件。既有 Android Views 示例继续作为源码与构建参考，设备运行范围见 [VALIDATION](../VALIDATION.md)。

浏览器附带规范和使用说明的只读快照，断网仍可查阅和预览；打开GitHub来源或发行页需要网络。源码链接固定到构建提交，不会默默切到更新后的main。运行程序不依赖维护源码；本机维护仓库统一保留在总目录的dev中。

## 外观、动画与保存位置

主题包括“暖纸护眼”“灰绿护眼”“浅色”“深色”，默认暖纸；这些是工作台的配色名称。默认100%正文为12pt，提供100% / 125% / 150%字号，对应正文12 / 15 / 18pt。这里调整应用字体，不改变 Windows 显示缩放。切换主题或字号时保留当前已打开预览的输入、真实进度、选择和禁用状态；切换到另一个条目会释放上一项预览，返回时创建默认实例。

动画可选“跟随系统”“正常动画”“减少动画”。减少动画取消装饰计时器，保留静态等待提示、忙碌状态和真实百分比；它不将真实任务标记为完成。离开实时预览页、最小化或关闭预览会暂停/释放对应动画；示例的模拟进度在隐藏期间暂停，回到预览后继续。组件接入目标应用时，由调用方同步自己的页面可见性与动画偏好。

v1.2.1中，仅以下3项外观偏好保存到实际EXE旁的`data/preferences.json`；本机约定位置为`D:\03_github_projects\UI_Center\data\preferences.json`。源码调试使用仓库内`work/data/preferences.json`，测试或调用方显式指定的路径优先。旧v1.2.0包仍使用旧同级路径，升级需同时迁移配置和更换EXE。

| 字段 | 可选值 | 默认值 |
| --- | --- | --- |
| `theme` | `warm` / `sage` / `light` / `dark` | `warm` |
| `font_scale` | `100` / `125` / `150` | `100` |
| `motion` | `system` / `normal` / `reduced` | `system` |

搜索、所选条目、预览参数、输入、任务进度和结果不持久保存。偏好文件不存在时使用默认值；读取异常时显示提示并回到默认外观；写入失败时当前会话的选择仍生效，程序会提示下次启动可能使用旧设置。data独立于可替换的EXE/_internal，升级保留；程序不自动搜索、迁移或写入旧同级目录。

使用帮助的“文件与保存位置”区域显示实际程序目录与当前设置文件，支持复制完整路径，以及打开程序/设置目录。目录尚未创建或打开失败时有明确提示；仅查看帮助不会创建文件夹。单文件模式同样使用实际EXE所在位置，不将设置放进临时解包目录。

Ctrl+F 定位搜索；Esc 优先关闭当前弹层，否则清除搜索；Tab / Shift+Tab 移动焦点。工作台不包含账号登录、在线 AI 调用、笔记编辑、收藏同步或自动更新。点击 GitHub 来源/发行入口时才打开浏览器。

## 更新与恢复

需要升级时手动打开 GitHub 发行页，先查看变更与未测范围，再下载完整新包。便携版使用同一发行的 EXE 和整个 `_internal`，不能混合不同版本。此前已复制到应用的组件不会随工作台自动更新，仍需按来源提交比较合并。

当前默认运行目录保持 `D:\03_github_projects\UI_Center`；升级只替换本次发行的 `UI_Center.exe` 与 `_internal`。其中dev为完整维护仓库，data为日常偏好，已有UI_Center_Private必须原位保留；不要清空总目录完成升级。候选、备份和工作记录在dev/work维护。首次从v1.2.0切换时，关闭旧程序后将旧Dev和Data整体移入dev/data，再使用验证过的新版EXE；不能让旧EXE继续保存设置。公开发布与本地清理分别需要对应授权。

程序“来源/关于”内容提供版本、固定提交、许可及源码入口；源码包保留构建脚本和锁定的打包工具。实际下载大小、解压大小、检查结果和是否已签名以该次发行说明为准。SHA-256 用于核对文件一致性，不代替开发者数字签名。

## 后续建议

- 日常只保留便携版，单文件 EXE 作为另一种分发选择保存在 GitHub，避免本机重复保存两套运行时。
- 界面优化任务先粘贴“条目 + 固定提交 + 目标项目约束”，比笼统要求“参考最新 UI”更容易复核与升级。
- 新增控件继续先覆盖相关的正常、禁用、忙碌、成功、取消和错误状态；实际用于两个独立项目后再考虑组件包。
- 若以后确实需要 Web 消费者，再引入 Web 实现或 Storybook；当前浏览器继续保持原生、小依赖和离线可用。
- 公开源码、必要测试和脱敏验证摘要；私钥、本机绝对路径和原始私人诊断记录不进入公共附件。
