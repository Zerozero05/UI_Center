# UI 设计规范

用途：为 Tkinter、Android 与未来 Web 实现提供共同的判断依据。这里的原则结合了[既有应用案例](cases.md)与[已核实来源](../references/sources.md)；具体组件能力和验证范围按平台说明执行。

## 视觉层次

一个区域先说明当前任务，再显示必要输入，最后呈现动作与结果。使用标题、正文、辅助文字三个字号角色，重复信息优先合并。强调色突出当前主动作；成功、警告与错误同时提供文字，避免只靠颜色区分。

默认采用系统字体。长文件名、路径和错误说明允许换行或横向查看，提供完整值的读取入口。检查当前选择与“准备执行”是否语义相同，不能只凭一套高亮同时表达多种状态。

## 布局与留白

相关控件就近分组，间距使用共享级别；平台自行换算点、dp 与字体缩放。窗口收窄时优先让内容区滚动或动作换行，保留主操作、结果和取消入口。外观切换保持用户输入、当前进度与布局状态。

首次布局、用户拖动和程序自动拉伸分别处理。示例的窗口大小不是所有应用的最低尺寸；需要布局记忆时仅记忆布局，不能连带重置业务设置。

## 主次操作

每个任务区突出一个主动作。辅助操作保持可发现，但降低视觉权重。菜单、按钮和快捷键复用同一处理逻辑及忙碌/输入校验。禁用时说明原因；可以取消的任务在运行时保留取消入口。

低频选项可折叠，但始终显示会影响结果的当前策略摘要。入口精简必须保持任务仍可完成。

## 反馈分级

| 情况 | 建议呈现 |
| --- | --- |
| 控件用途说明 | 邻近说明或可关闭的帮助，不抢焦点 |
| 常规完成或取消 | 持续可见的状态与结果区 |
| 输入错误 | 就地指出字段和修正方法，保留输入 |
| 任务失败 | 保留可读错误、已完成数量及下一步 |
| 覆盖、删除、未保存资料 | 按目标项目风险使用明确确认 |

重要错误不只通过自动消失的轻提示传递。任务中的进度表达实际已完成数量；未知总量时不用虚假的百分比。

## 键盘与焦点

操作顺序与视觉顺序一致；Tab 焦点可见，输入框保留文字编辑语义。快捷键限定到相关区域，尊重当前编辑、选择和忙碌状态。弹窗关闭后返回合理焦点；触控端使用明确标签与足够点击区域。

键盘操作必须在真实窗口验证；主题参数存在不能证明焦点边框可见。Android 同时检查系统字体放大与外接键盘需求。

## 明暗主题

使用[设计参数](../tokens/README.md)的语义角色，避免在组件内另造配色副本。覆盖正常、悬停/按下、焦点、选中、禁用与错误状态。Tk 原生系统对话框和 Android 系统界面有各自范围，按实际行为说明。

切换主题只改变呈现，保留输入、任务和结果。内容图片采用原像素；无明确需求不随暗色主题修改文档或图片颜色。
