# 案例与兼容边界

## Windows 文档工具

来源：[PDF_Bookmarks 固定提交](https://github.com/Zerozero05/PDF_Bookmarks/tree/0097a07ba494e3376fab680e880bf2d2a1ced66c)。

- **问题**：控件层次、主题状态、主次操作与任务反馈需要统一，界面改动仍应保留原任务行为。
- **采用**：从 ui_theme.py 提炼 clam 样式与语义配色的应用策略；操作区和主线程反馈方法用于独立模拟示例。
- **调整**：移除 PDF、OCR、应用图标及特定业务依赖；参数改由公共 JSON 提供；任务由示例持有。
- **适用边界**：原程序的双标签、具体窗口尺寸、专注模式、15项自定义快捷键、护眼主题与文件事务都是该程序决定，未推广为本中心强制规范。
- **源码/许可**：实际改编范围和原始版权见[来源记录](../references/sources.md)；保留 AGPLv3。

## Android 文档工具

来源：[PDF_Bookmarks_Android 固定提交](https://github.com/Zerozero05/PDF_Bookmarks_Android/tree/b44ab5d14e547fef4b80e9469b7c8eb503e2302e)。

- **问题**：原生 Views 的外观、忙碌状态与结果摘要需要在窄屏和横屏中保持可读。
- **采用**：提炼主题、操作分组、进度与结果呈现；原应用行为作为取消及状态恢复的参考。
- **调整**：独立应用身份，使用虚构条目，不处理 PDF、目录、存储授权和更新事务。
- **适用边界**：原应用的文件访问、享做同步、授权管理、签名及升级流程保留在来源项目，不成为通用组件接口。
- **源码/许可**：实际改编范围和原始版权见[来源记录](../references/sources.md)；保留 AGPLv3。

## 如何记录新案例

每个案例记录：原问题、所用 UI_Center 提交、采用的规范/组件、平台差异、原功能保护、实际验证及未覆盖项。应用内已有结果只有在代码、环境和范围仍相同时才能复用，不能自动当作本中心示例已通过的证据。
